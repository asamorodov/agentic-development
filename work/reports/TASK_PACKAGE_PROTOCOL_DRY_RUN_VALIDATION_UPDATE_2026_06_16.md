# TASK_PACKAGE_PROTOCOL_DRY_RUN_VALIDATION_UPDATE_2026_06_16

Статус: протокольная правка после обнаруженной ошибки упаковки staged executor package.

## Причина

В одном из собранных пакетов runner перешёл к записи, которая требовала файл, ещё не созданный предыдущими рабочими листами. Это было не содержательной ошибкой модели и не проблемой длины блока, а дефектом цепочки записей и зависимостей после изменения порядка исполнения.

## Что изменено

Обновлены общие протоколы упаковки:

```text
work/protocols/TASK_PACKAGE_CREATION_PROTOCOL.md
work/protocols/TASK_PACKAGE_MANUFACTORY_PROTOCOL.md
```

В них добавлено универсальное правило полного сухого прогона runner-цепочки перед выдачей длинного, стадийного или перестроенного пакета.

Сухой прогон не выполняет содержательную работу. Он последовательно материализует рабочие листы, создаёт пустые заглушки только для обязательных выходов текущего листа, проверяет следующий переход, проходит плановые остановки через штатный `continue` и доходит до финальной записи.

## Что именно проверяется

- `unzip -t`;
- первый рабочий лист;
- целостность всех переходов runner-а;
- stage-stop / continue;
- отсутствие требования будущих файлов раньше времени;
- максимальная длина участка между плановыми остановками;
- наличие отчёта `PACKAGING_VALIDATION.md`.

Пакет считается неверно собранным, если любая запись требует файл, который не входит в исходные материалы пакета и не был создан одним из уже пройденных рабочих листов сухого прогона.

## Граница правки

В протокол намеренно не внесены правила, специфичные для мини-досье, статей Атласа или конкретной статьи A2. Протокол говорит только об универсальной целостности runner-цепочки, зависимостей, плановых остановок и validation report.
