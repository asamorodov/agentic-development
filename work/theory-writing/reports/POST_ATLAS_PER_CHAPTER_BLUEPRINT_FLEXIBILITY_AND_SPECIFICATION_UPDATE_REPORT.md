# Отчёт: уточнение blueprint для планов послеатласных глав

Дата: 2026-06-14.
База: cumulative overlay относительно `git(12).zip`.

## Что изменено

Уточнён `work/theory-writing/reports/POST_ATLAS_PER_CHAPTER_TARGET_PLAN_BLUEPRINT.md`. Цель правки — не менять проверенную на главе II схему, а убрать места, где blueprint мог снова порождать механические или чрезмерно подробные планы.

Основные изменения:

- Зафиксировано, что базовая очередь не является обязательной формой на 22 прохода. План может быть короче или длиннее: длина очереди должна отражать сложность главы, количество аспектов для добора, объём внешнего поиска, работу с изображениями и риск обзорности.
- Добавлено требование: каждый конкретный план явно выбирает профиль внешнего поиска `D0`, `D1`, `D2` или `D3` и коротко объясняет выбор.
- Уточнено, что считается существенным содержательным изменением: новый источник, сцена, различение, раздел, пример или правка хода аргумента. После такого изменения переписывается затронутый раздел; всю главу переписывать нужно только при изменении общей логики.
- Проверка источников разведена с письмом: она ищет проблемы ссылок и происхождения утверждений, но не должна сама становиться редакторским проходом. Если нужно менять абзац, это делается как локальная русская перепись.
- Визуальный шаг уточнён: если фигура вставляется, основной текст должен объяснить, зачем она нужна. Если кандидат полезен, но не готов к вставке, оставляется конкретная запись для последующей работы, а не общая пометка.
- В критерии готовности добавлено, что план не должен быть механической копией blueprint и не должен превращаться в мини-главу. Он задаёт направление, материалы, риски и критерии; конкретные объяснения и формулировки появляются уже в исполнительном пакете.
- Старый англоязычный список проходов в разделе `Что больше не использовать` заменён русской формулировкой.
- Добавлена заметка: старые планы нельзя чинить поверх прежней очереди. При пересборке их нужно сначала перестроить под новую логику, а потом переписать сам план естественным русским языком.

## Словарь

В `protocols/rules/conceptual-translation-glossary.md` добавлена запись про `долг`. Слово допустимо для настоящего технического долга, но не для обычных планировочных случаев вроде `визуальный долг`, `долг для другой главы`, `оставить долг`. Предпочтительные формы: `открытый вопрос`, `отложенная задача`, `кандидат для последующей работы`, `тема для другой главы`, `запись для последующей работы`.

## Проверки

- Blueprint содержит требование явного профиля внешнего поиска `D0`–`D3`.
- Blueprint говорит, что очередь может быть меньше или больше 22 проходов.
- Blueprint содержит определение существенного содержательного изменения.
- В активном тексте blueprint нет слова `долг` в прежнем планировочном смысле.
- Словарь содержит отдельную запись про `долг`.
- Markdown fences в изменённых файлах сбалансированы.
