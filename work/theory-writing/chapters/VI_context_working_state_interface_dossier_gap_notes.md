# Chapter VI — dossier gap notes

Досье уже во многом покрывают материал для VI. Дополнительный внешний поиск может быть полезен, но не должен расширять главу до обзора инструментов. Главные пробелы касаются не фактов о методах, а подтверждения актуальных поверхностей `AGENTS.md`, `skills`, hooks, MCP, subagents и правил включения контекста.

## Kiro

Материал достаточен для основной главы: Атлас и досье покрывают Specs, steering, `#spec`, hooks, Sync Files, MCP/Powers и subagents. Нужно проверить только актуальные публичные страницы, если финальная глава будет ставить точные ссылки рядом с конкретными механизмами.

Риск: увести VI в продуктовый обзор Kiro. Нужно брать только контекстные слои и состояние spec.

## Spec Kit

Материал достаточен для роли Spec Kit в VI. Нужно не перечислять все команды, а показать команды как переходы состояния и `constitution` как долговременное правило.

Риск: повторить главу V про защищённые спецификационные профили.

## BMAD

Материал достаточен для состояния работы: `project-context.md`, `story`, `sprint-status.yaml`, checkpoint preview, `correct-course`, retrospective. Досье полезно как gap-check, но не как источник нового каталога ролей.

Риск: превратить VI в главу VIII про процессные профили.

## GSD / Open GSD

Материал богатый, но опасный для границы с IX. В VI брать только `.planning/`, state-файлы, контекстный режим, маршрутизацию и восстановление как проектный интерфейс. Детали среды выполнения, Git-изоляции, SQLite и автоматического режима лучше оставить для VIII/IX.

Риск: смешать процессный профиль, среду исполнения и PWG.

## Persistent Work Graph

Досье нужно в VI только для мостового участка. Основная разработка PWG остаётся для VII. В VI достаточно показать, что обычные файлы состояния и story/status-артефакты ещё слабее, чем граф работы, потому что не всегда дают готовность, блокировки, владение, gate и prime.

Риск: преждевременно раскрыть VII.

## Внешний discovery gap

Для финального текста желательно добавить первичные ссылки на официальные или внешне читаемые источники по следующим поверхностям:

- `AGENTS.md` / проектные инструкции в Codex, Claude Code или Kiro;
- Claude skills или похожие skill-механизмы;
- hooks в Kiro / Claude / Codex, если глава использует их как пример привязки правила к действию;
- MCP как источник возможностей и риска контекстного шума;
- subagents как распределение прав и типа работы.

Но внешний поиск должен быть ограничен: цель — подтвердить и уточнить механизмы, уже выбранные из внутренних материалов, а не добавить новый список инструментов.

## Дополнение P05: решение по пробелам

Внутренние материалы достаточны для первого полного черновика. Для финального текста всё же нужен ограниченный внешний discovery, потому что механизмы `AGENTS.md`, `skills`, hooks, MCP и subagents быстро меняются и должны получить точные публичные ссылки. Добор источников должен идти после композиционного решения, а не до него: сначала определить, какой механизм нужен главе, затем найти первичный источник под этот механизм.

## P19 — состояние пробелов после интеграции

Пробелы, отмеченные раньше, в основном закрыты внешним discovery и интеграцией источников: `AGENTS.md`, skills, hooks, MCP, subagents, Kiro Specs/Steering/Powers, BMAD, GSD и Spec Kit получили первичные ссылки в тексте.

Оставшиеся ограничения осознанные:

- глава не раскрывает полную модель PWG;
- глава не разбирает sandbox, approvals, permissions и durable execution;
- история Stripe используется только как пример отобранного корпоративного интерфейса, без утверждений о качестве всех Minion PR;
- история Erikson используется как малый интерфейс проектной памяти, без полного разбора его review/permission tooling.

Новых источников для VI сейчас не требуется, если следующий проход не выявит конкретную фактическую дыру.

## P20 — состояние после русской переписи

После переписи новые story/dossier материалы не требуют внешнего добора. Оставшийся риск — не фактический, а композиционный: глава стала насыщенной, поэтому следующие проверки должны смотреть на последовательность и перегруз примерами, а не на поиск дополнительных источников.

## P30 final gap check

Фактические пробелы, отмеченные в начале работы, закрыты для уровня этой главы. В тексте есть первичные или публичные ссылки на `AGENTS.md`, `CLAUDE.md`, Kiro Specs/Steering/Powers/Hooks/Subagents, Claude Skills/Hooks/Subagents/MCP, MCP specification, BMAD, GSD, Spec Kit, а также на выбранные story-опоры.
